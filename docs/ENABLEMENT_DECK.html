The Problem

Databricks is a black box
inside your monitoring estate

Operational

No single pane of glass

Job failures, cluster anomalies, and slow queries are visible only in the Databricks UI — workspace-scoped, no cross-workspace view, no integration with the rest of your monitored infrastructure.

Financial

Cost surprises at month end

DBU consumption and estimated costs are buried in system tables that require SQL expertise to interrogate. Teams learn about cost overruns from their cloud bill, not from monitoring alerts.

Data Quality

Silent data reliability failures

DLT pipeline data quality expectations fail quietly. Data consumers find the problem before the engineering team does — from bad BI reports or failed ML model inputs.

The result: Databricks teams operate reactively. Incidents are reported by downstream consumers, cost spikes are discovered at billing time, and data quality failures are invisible until they cause business impact.

Market Landscape

Why existing tools fall short

Datadog

Cost visibility = paid add-on

DBU cost monitoring requires the Cloud Cost Management SKU — a separately priced product that pulls from cloud provider billing APIs (AWS Cost Explorer, Azure Cost Management). Not included in standard Databricks monitoring. Requires additional commercial negotiation.

Data quality: No DLT expectation monitoring.

New Relic

System table licence required

New Relic's cost dashboards use the same system.billing.usage source we use, but require a Databricks system table licence to be enabled. Limited differentiation from our approach with no additional advantage.

Model serving: No endpoint monitoring.

Databricks UI

Siloed and workspace-scoped

The native Databricks UI provides rich detail per workspace but has no cross-workspace aggregation, no integration with non-Databricks infrastructure, no alert routing, and no RBAC alignment with the broader monitoring platform.

Monitoring teams: Cannot monitor without a Databricks account.

The gap: No existing tool provides Databricks-native cost intelligence, DLT data quality monitoring, and model serving observability in a single platform — inside the monitoring tool organisations already own.

Compute

Query Intelligence

  • Query history — up to 25 per warehouse

  • Bytes read, rows produced, cache hit

Model Serving

  • Endpoint inventory — state, creator

  • Served model name, version, deployment state

Value Selling Framework

The business case

1

Business Issue

Databricks environments generate cost, risk, and data quality events that are invisible to the operations team. Platform engineers spend hours per week context-switching between Foglight and the Databricks UI to diagnose issues they should be alerted to automatically.

2

Problem

No Foglight cartridge exists for Databricks. Monitoring is manual, reactive, and workspace-scoped. Cost overruns are discovered at month end. Data quality failures surface via downstream complaints, not alerts. There is no single view of the Lakehouse estate.

3

Solution

Foglight for Databricks — a native cartridge collecting compute, job, query, cost, pipeline, and model serving data every 60 seconds. 25 portlets, no new infrastructure, no additional SaaS. Installs in under 30 minutes.

4

Value

Operational: Proactive alerting on job failures, cluster anomalies, slow queries.

Financial: DBU cost visibility before the cloud bill arrives.

Data reliability: DLT expectation failures surfaced before data consumers are impacted.

5

Why Quest

Databricks-native cost intelligence included (not a paid add-on). First monitoring platform to surface DLT data quality expectations. Extends the existing Foglight investment — no new vendor, no new contract, no new platform to learn.

Getting started

Requirements

  • Quest Foglight Management Server 8.2.0+
  • FglAM co-located with FMS (existing deployment)
  • Databricks Personal Access Token — read only
  • Any running SQL Warehouse (for cost features)
  • Databricks Standard plan for core features
  • Databricks Premium + system tables for DBU/cost

Installation — under 30 minutes

  • Download release zip from GitHub
  • Copy agent files to FglAM agents directory
  • Edit databricks.properties with workspace URL + token
  • Install .car via Foglight UI → Administration → Cartridges
  • Restart FglAM — data appears within 60 seconds
